# ADR-0007: Destination subthreads and commerce routing

- Status: accepted for MVP
- Date: 2026-07-15

## Context

Основной chat управляет критериями всей поездки и живой лентой рекомендаций. Пользователю также
нужно обсуждать конкретную карточку: район для проживания, места рядом, риски и отличие от других
вариантов. Если смешать такие вопросы с основным transcript, локальное обсуждение направления
становится неотличимо от глобального уточнения критериев и может неожиданно перестроить shortlist.

Карточка одновременно является переходом из этапа выбора направления к поиску билетов и жилья.
Эти переходы должны быть понятными, заменяемыми по провайдеру и измеримыми как продуктовые события.

## Decision

### Destination subthread

Каждая актуальная карточка получает действие «Обсудить направление». Оно открывает вложенный
subthread в правой панели, не добавляя сообщения в основной chat. На мобильном тот же subthread
открывается как вложенный полноэкранный экран с возвратом к вариантам.

Subthread:

- идентифицируется парой `session_id + destination_id`;
- наследует подтверждённый `TravelRequest` и текущий снимок карточки;
- хранит отдельную bounded-историю до 20 последних сообщений;
- использует общий process-scoped `ModelGateway`, а не отдельного автономного агента;
- не запускает ranking и не изменяет критерии основной поездки;
- может вернуть предложение применить явно сформулированное ограничение ко всей поездке.

Применение ограничения всегда является отдельным подтверждённым действием пользователя. После него
текст ограничения отправляется как обычный refinement основного chat и проходит существующий
детерминированный pipeline.

Backend memory subthreads хранится в checkpoint state основного LangGraph thread. UI transcript
дополнительно хранится в существующем `localStorage` presentation cache. Отдельный graph и
multi-agent orchestration не добавляются.

### API contract

`POST /destination-chat` принимает `session_id`, `destination_id` и `query`. Endpoint отклоняет
неизвестную поездку или направление, которого нет в текущем shortlist. Ответ содержит текст,
короткие варианты следующего вопроса и optional `proposed_trip_change`, но никогда не применяет
этот patch автоматически.

### Card routing

Внизу карточки остаются две главные CTA:

1. слева «Найти билеты · Aviasales»;
2. справа «Найти жильё · Яндекс Путешествия».

Aviasales URL получает известные origin/destination IATA, пассажиров и только подтверждённые точные
flight dates по контракту [ADR-0008](0008-aviasales-deeplink-contract.md). Если известен лишь месяц
или примерный диапазон, дата не выдумывается и открывается форма выбора дат.
Яндекс Путешествия получает destination-specific hotel URL из routing-слоя карточки. Ни одна ссылка
не считается evidence наличия или цены.

Каждый переход отправляет best-effort anonymous event `travel_link_opened` с `session_id`,
`request_id`, `destination_id`, позицией карточки, provider и link kind. Ошибка аналитики не должна
мешать навигации.

### Observability

Langfuse `session_id` по-прежнему соответствует всей поездке. Каждый основной или destination turn
остаётся отдельным trace, чтобы сохранять корректные latency, cost и error boundaries. Traces
получают человекочитаемые имена `Turn NN · <kind>`; destination turn также содержит
`subthread_id` и `destination_id`.

## Consequences

- Основной chat остаётся журналом глобальных решений, а карточка получает локальный контекст.
- Пользователь может вернуться к обсуждению нескольких направлений независимо.
- Критерии поездки не меняются неявно из локального разговора.
- CTR билетов и жилья можно сравнивать по направлению и позиции карточки.
- Bounded state ограничивает размер checkpoint и prompt; до public beta всё ещё нужны retention и
  server-side индекс anonymous sessions.

## Rejected alternatives

- Один общий transcript: локальные вопросы и глобальные refinements становятся неоднозначными.
- Modal для subthread: плохо поддерживает длинную переписку и мобильную навигацию.
- Отдельный автономный агент на карточку: усложняет topology и не даёт ценности для текущего MVP.
- Один Langfuse trace на всю жизнь chat: длительность и ошибки отдельных HTTP turns становятся
  неинформативными.
