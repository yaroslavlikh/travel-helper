# Product brief

Статус: accepted для MVP. Последнее обновление: 2026-07-14.

## Проблема

Выбор направления обычно требует вручную сопоставить бюджет, даты, погоду, визовые ограничения, перелёт и личные предпочтения. Информация разбросана по источникам, быстро устаревает и часто представлена как несопоставимые точечные значения.

Travel Choice Assistant принимает естественный запрос, выясняет только критически недостающие ограничения и возвращает 3–5 объяснимых вариантов с диапазонами бюджета, рисками, допущениями и источниками.

Пример: «Живу в Москве, хочу улететь на море в августе на 7–10 дней, бюджет 150 тысяч рублей на одного, не люблю сильную жару».

## Job to be done

Когда я ещё не выбрал направление, я хочу быстро получить небольшой shortlist, сопоставимый по одним критериям и подкреплённый актуальными источниками, чтобы принять решение о дальнейшем самостоятельном поиске или бронировании.

## Пользовательский сценарий MVP

1. Пользователь без регистрации попадает в автоматически созданный пустой chat и вводит свободный запрос.
2. Система извлекает ограничения, не заполняя неизвестные поля догадками.
3. Если отсутствуют P0-данные, система задаёт не более трёх вопросов.
4. Ответ продолжает тот же anonymous thread.
5. Система ищет кандидатов и evidence во внешних источниках.
6. Hard filters удаляют заведомо неподходящие варианты с машиночитаемой причиной.
7. Оставшиеся варианты получают детерминированный score.
8. UI показывает 3–5 карточек конкретных городов/регионов с фотографиями, местами, assumptions,
   warnings, раскрываемыми sources и CTA поиска билетов в Aviasales и жилья в Яндекс Путешествиях.
   В Aviasales передаётся только маршрут origin/destination; пользователь выбирает даты в
   календаре провайдера.
9. Пользователь может открыть вложенный subthread карточки и обсуждать конкретное направление, не
   меняя условия всей поездки без отдельного подтверждения.
10. Пользователь уточняет условия в основном chat; система обновляет TravelRequest и живую ленту,
   сохраняя заданные вопросы и ответы в transcript.
11. Пользователь оставляет простую оценку результата.

## Принципы продукта

- Evidence before eloquence: объяснение не может расширять набор подтверждённых фактов.
- Диапазоны вместо ложной точности: стоимость показывается интервалом и с freshness.
- Уточнять только то, что меняет поиск или hard filters.
- Не скрывать defaults, конфликты источников и деградацию провайдеров.
- Один понятный shortlist важнее большого каталога.
- Chat является способом менять критерии, а live feed — единственной актуальной версией результата.

## Границы MVP

В MVP входят: anonymous sessions, natural-language input, clarification loop, search-based candidate generation, evidence normalization, hard filters, deterministic scoring, responsive web UI, sources, warnings, feedback и operational tracing.

В MVP не входят: регистрация, оплата, бронирование, личный кабинет, мобильное приложение, multi-agent orchestration, универсальная vector/RAG база, собственный crawler и рекомендательная ML-модель.

## Приоритеты неоднозначностей

- P0: без ответа нельзя корректно искать или применить hard filter. Примеры: origin, период, travelers, приблизительный budget, domestic/international scope.
- P1: заметно меняет ranking, но допускает показанный default. Примеры: visa willingness, baggage, date flexibility, flight duration, budget strictness.
- P2: персонализация, которая не останавливает поиск. Примеры: nightlife, beach type, cuisine, city size.

Система задаёт максимум три вопроса за один interrupt, сначала P0. Уже известные поля повторно не спрашиваются.

## Метрики первой публичной версии

- Пользователь доходит до shortlist без ошибки.
- Доля запросов, завершившихся 3–5 рекомендациями.
- Доля partial результатов и причины деградации.
- Число clarification turns до результата; целевое значение — 0 или 1 для большинства достаточно полных запросов.
- Positive feedback rate, source-open rate и CTR provider CTA по позиции карточки.
- P50/P95 latency по стадиям pipeline.

Целевая нагрузка MVP: около 100 пользователей до конца июля 2026 года. Это не требует микросервисов, очередей или раннего горизонтального масштабирования.

## Нерешённые продуктовые вопросы

- Какие citizenship/origin combinations являются первым поддерживаемым рынком.
- Требуется ли обязательный ввод гражданства для international scope или достаточно явного assumption.
- Максимально допустимая end-to-end latency.
- Срок хранения anonymous thread state и feedback.
- Какие источники считаются достаточными для публичного запуска.
